第3回：for文・総和・パラメータ作図

今回は，同じ処理を繰り返す「for文」 と，繰り返しのなかで値を 1つずつ足していく（足しこむ） ことで総和を作る方法を学ぶ． 足しこみは，第1回の 再代入 s = s + x をループの中で繰り返すものである． そして第2回の「図形を丸ごと描く」を 「重ね描き」 へ展開し， パラメータを変えながら曲線を何本も重ねる（題材＝ローレンツ関数）．

ノート今回のキーワード
  • 繰り返しは 値を走査する for x in xs（x が xs の中身を順に受け取る）．
  • 足しこみの 初期化はループの外．s = 0 を中に書くと毎回リセットされてしまう．
  • 重ね描きは plot ＝新規・plot! ＝追記 の区別が肝．

for文：同じ処理を繰り返す

for x in xs … end と書くと，x が xs の中身を順に受け取り，そのたびに … の部分が実行される． これを for文（繰り返し） という．まずは中身を表示するだけのループを見てみよう． 表示には println を使う．println(x) は x の値を1行に表示して改行する命令である． セルは最後の値だけを表示するので，途中経過を見るには println が要る．

for x in [10, 20, 30]
    println(x)        # x takes each element of the vector in turn
end
10
20
30
ノート

ここで使うのは 値そのものを走査する for x in xs の形である． x が xs の中身を順に受け取る，と読めばよい．

ノート添字の補足：end-1

第2回で，a[end] は最後の要素だった．end は 最後の番号 を表すので， end-1 は 最後の1つ前 の番号になる． したがって a[end-1] は最後から2番目の要素，a[1:end-1] は 最後を除く全部 である．

a = [10, 20, 30, 40]
@show a[end-1]       # one before the last
@show a[1:end-1]     # all but the last
a[end - 1] = 30
a[1:end - 1] = [10, 20, 30]
3-element Vector{Int64}:
 10
 20
 30

総和：再代入を繰り返して足しこむ

第1回で x = x + 1（右辺を今の値で計算 → 名前を貼り替え）をやった． これをループの中で繰り返すと，値をためていく ことができる． なお s = s + x は s += x と短く書ける（意味は同じ）．以降の回でもこの書き方が出てくる．

重要予測しよう（L1）

次のセルで，最後の s はいくつになるか，実行する前に予想しよう． 各回のループのあと s がどう変わるかを，下の表に書き出すとよい．

x 実行後の s（予測）
1
2
3
4 
s = 0                      # initialize (outside the loop!)
for x in [1, 2, 3, 4]      # iterate over the values themselves
    s = s + x              # update s each time (reassignment)
end
s                          # compare with your prediction
10

頭の中で1行ずつ追うことを トレース（机上実行）という．表と実行結果は一致しただろうか．

既知の和の公式と照らし合わせる（L2）

予測して実行するだけ（L1）では「合っているつもり」で終わりかねない． 別の方法で答えを知っているなら，それと照合できる（L2）． 1 から 100 までの和は，公式 \(\,n(n+1)/2\,\) から 5050 だと分かっている．

重要予測しよう（L1→L2）

1:100 を走査して足しこんだ s は，公式の 100*101/2 と一致するだろうか？

s = 0
for x in 1:100             # iterate over the range 1:100
    s = s + x
end
s                          # compare with the formula below
5050
100 * 101 ÷ 2              # check against formula n(n+1)/2 (match)
5050
ノート

÷ は整数どうしの 商（割り切った値）を返す演算子である（\div と打って TAB で入力する）． div(100 * 101, 2) と関数の形で書いても同じで，整数の割り算は第9回でくわしく扱う． ここでは「公式の値と足しこみの結果が一致する」ことだけ確認できればよい．

落とし穴の例1：s = 0 をどこに書くか

足しこみでいちばん多い失敗が，初期化 s = 0 をループの中に書いてしまう ことである．

重要予測しよう（L1）

次のコードは s = 0 が ループの中 にある． さきほどと同じ [1, 2, 3, 4] を足すが，結果は 10 になるだろうか．

s = 0
for x in [1, 2, 3, 4]
    s = 0                  # <- reset every iteration (pitfall)
    s = s + x
end
s                          # compare with the 10 you got above
4

各回の頭で s がリセットされるので，足し算が積み上がらず，最後の要素しか残らない． 既知の答えと食い違うことで誤りに気づける．これがL2検証の力である． 初期化は ループの外 に置く，と肝に銘じよう．

では，初期化を 書き忘れた らどうなるか．

重要予測しよう（L1）

total は，まだどこにも定義していない名前である． 次のセルを実行すると，エラーになるだろうか．なるとしたら，どの行でなるか． （ヒント：[] は要素が1つもない空のベクトル．ループの中は何回実行されるか．）

@errmsg begin
    for x in []                # empty vector
        total = total + x      # total was never initialized
    end
    println("after the loop")
    total
end
after the loop
UndefVarError: `total` not defined in `Main.Notebook`
Suggestion: check for spelling errors or missing imports.

ループの中は 一度も実行されない ので，ループではエラーにならない． エラーは，最後に total を使った行で初めて出る（after the loop は表示されている）． 空でないベクトルなら，1回目の total + x でエラーになる． 間違いがあっても，実行されない行ではエラーは出ない．エラーが出た行と，間違えた行は同じとは限らない． s = 0 のように外で初期化しておけば，空のときの総和は 0 になる．

ただし，名前が すでに定義されている ときは，エラーにならない． たとえば s は上のセルで定義済みなので，s = 0 を書き忘れても，ループは その時点の s の値に続けて足しこむ． エラーが出ないぶん，気づきにくい．答えが既知の値（L2）と食い違ったら，初期化を疑おう．

ローレンツ関数：パラメータでピークの幅が変わる

ここからは作図に移る．題材は ローレンツ関数

\[ L(t) = \frac{1}{1 + (t/\gamma)^2} \]

である．これは t = 0 で ピーク 1 をとり，左右になだらかに下がる 山型の曲線で， 共鳴やスペクトル線の形としてよく現れる．幅は パラメータ γ（ガンマ） で決まる．

第2回と同じく，ブロードキャスト式 で L の値を一気に計算する． プロットには Plots パッケージを使う（自分で書き始めるときは最初に一度 using Plots）．

using Plots

まず γ = 1.0 の1本だけ描いてみる．t を範囲で作り，要素ごとに y を計算する．

警告落とし穴：ドット（.）を忘れると

t はベクトルなので，1/(1+(t/γ)^2) と書くとエラーになる． ベクトルの べき乗 (…)^2 と，スカラー ＋ ベクトル 1 + … が定義されていないためである （第2回の峻別）．要素ごとに計算するには 1 ./ (1 .+ (t / γ).^2) と書く． t / γ は スカラーでの割り算（伸縮）なので，ドットを付けなくてよい（付けても同じ結果になる）．

t = -5:0.1:5
γ = 1.0
y = 1 ./ (1 .+ (t / γ).^2)    # Lorentzian (dots only where needed)
plot(t, y)
重要半値で照合しよう（L2）

t = γ のとき，\(L(\gamma) = 1/(1 + (\gamma/\gamma)^2) = 1/(1+1)\) になる． つまり ピークの半分（0.5） のはずである．確かめてみよう．

γ = 1.0
1 / (1 + (γ/γ)^2)             # the value at t = γ
0.5

重ね描き：plot と plot!

複数の曲線を 1枚に重ねる には，2種類の命令を使い分ける．

  • plot(...) … 新しい図を描く（前の図は消える）．
  • plot!(...) … 今の図に 重ねて追記する（! 付き）．

そこで，plot() で空の図を用意 → ループの中で plot! を繰り返す という型を使えば， パラメータ γ を変えながら何本でも重ねられる．

重要予測しよう（L1）

次のセルは曲線を 何本 描くか？ また，γ を 0.5, 1.0, 2.0 と大きくすると，山の幅は 広くなるか・狭くなるか？

t = -5:0.1:5
plot()                              # prepare an empty plot
for γ in [0.5, 1.0, 2.0]            # iterate over the width γ
    y = 1 ./ (1 .+ (t / γ).^2)      # Lorentzian (dots only where needed)
    plot!(t, y)                     # overlay (append)
end
plot!()                             # display at the end

3本の曲線が重なって描かれる．どれも t = 0 でピーク 1 を通り， γ が大きいほど山は広く（なだらか），小さいほど鋭く尖る．

落とし穴の例2：plot! を plot にすると

重ね描きでの定番の失敗が，ループの中で plot!（追記）を plot（新規）にしてしまう ことである．

重要予測しよう（L1）

下のコードはループの中が plot（! 無し）になっている． 3回まわったあと，曲線は何本描かれているだろうか．

t = -5:0.1:5
for γ in [0.5, 1.0, 2.0]
    y = 1 ./ (1 .+ (t / γ).^2)
    plot(t, y)                      # <- new each time (pitfall)
end
plot!()                             # how many curves do you see?

毎回 前の曲線が消されて描き直されるので，残るのは最後の1本だけである． 「3本のはずが1本」 と本数が合わないことで気づける．

ノートアルゴリズムを図で見る（反復の箱）

総和も重ね描きも，「初期化 → 同じ処理を繰り返す」 という同じ骨組みである． 手元で，繰り返す処理を 反復の箱（同じ手順を囲んだ枠）として描くと， 「初期化はループの外，更新はループの中」という構造が目で見て分かる．

今回のまとめ

  • for文 for x in xs … end は，x が xs の中身を順に受け取って処理を繰り返す（値の走査）．
  • 総和 は s = s + x の繰り返しで作る．初期化 s = 0 はループの外（中に書くと最後の要素だけになる）．
  • 結果は 既知の公式と照合（1:100 の和 ＝ 100*101/2 ＝ 5050）して検証する（L2）．
  • 重ね描きは plot ＝新規・plot! ＝追記．plot() → ループで plot! が重ね描きの型．
  • ローレンツ関数 1 ./ (1 .+ (t / γ).^2) は山型のピーク曲線．γ が大きいほど幅が広い．t=γ で半値 0.5．

この回で使った関数

  • println（日本語訳）
  • plot／plot! … Plots.jl のドキュメント（日本語訳なし）

  3. 落とし穴の例1（初期化が内側）と落とし穴の例2（plot! を plot に）を，それぞれ正しく直し，「直したら結果がどう変わったか」を箇条書き（-）で説明せよ．
