発展：ファイルとパス

ノートこの資料について

これは 発展 であり，必修ではない．取り組むかは自由で，成績の素点には含めない． 第3回までの道具（変数・ベクトル・for・println）だけで読める．

扱うのは，計算機がファイルをどう並べているかと，Julia からその場所をどう指すかである． レポートに図を貼る，データを読む，結果を保存する——どれもここが分かっていないと詰まる．

ノートこの資料のキーワード
  • ファイルを触る前に pwd() で自分のいる場所を確かめる．
  • 区切り文字（\ か /）は 自分で書かず joinpath に任せる．
  • 書いたら 確かめる．isfile と読み戻しで照合する（第3回までの「照合」と同じ）．

自分がどこにいるか

計算機の中のファイルは，フォルダ（ディレクトリ）が入れ子になった木の上に置かれている． プログラムは，その木のどこか1か所に いま居る．そこを カレントディレクトリ という．

"hello.txt" のようにフォルダ名を付けずに書いたファイル名は，いま居る場所にあるものを指す． だから，いま居る場所が分からないままファイルを読み書きすると， 「書いたはずのファイルが見つからない」ことになる．

重要予測しよう（L1）

次のセルは何を表示するだろうか． 自分のPCのどのフォルダが出てくるか，実行する前に見当をつけよう．

pwd()                     # where am I now?
"/Users/hs/Documents/__Class/26w-MSE-prog/memoProgClass2026w-work"

これが いま居る場所 である．ファイルを触る前に，まずこれを実行する．

同じ notebook でも，VS Code で開いたときと Jupyter で開いたときで違う値になることがある． だから「自分はここにいるはず」と思い込まず，毎回確かめる．

ノート2通りで動かして比べる

この資料は notebook（.ipynb） と スクリプト（.jl） の2つの形で配ってある． 中身のコードは同じものである．

pwd() を両方で実行して，同じ値になるかを確かめてみよう． 同じなら「この環境では一致する」，違うなら「開き方で変わる」と分かる． どちらであっても，確かめたことに意味がある．

次に，いま居る場所に何が置かれているかを見る．

パスを組み立てる

ファイルの場所を表す文字列を パス という．2種類ある．

  • 相対パス … いま居る場所からの道順．"hello1.txt"，"data/a.csv"
  • 絶対パス … 木の一番上からの道順．"C:/Julia/PKG"，"/Users/hs/a.txt"

相対パスは短くて済むが，いま居る場所が変わると意味が変わる． 絶対パスは長いが，どこから実行しても同じ場所を指す．

パスをつなぐときは，* で文字列を貼り合わせるのではなく joinpath を使う．

重要予測しよう（L1）

joinpath("data", "a.csv") は何を返すだろうか． 区切り文字は何になるか，実行する前に予想しよう．

joinpath("data", "a.csv")      # join parts into one path
"data/a.csv"

区切り文字は OS が決める．Windows なら \，macOS や Linux なら / になる． 自分で区切り文字を書かないのが要点である．joinpath に任せれば，どのOSでも正しくなる．

pwd() と組み合わせると，いま居る場所を基準に 絶対パス を作れる．

joinpath(pwd(), "hello1.txt")  # absolute path, built from where we are
"/Users/hs/Documents/__Class/26w-MSE-prog/memoProgClass2026w-work/hello1.txt"

パスを分解する関数もある．

[basename("/a/b/fig.png"), dirname("/a/b/fig.png")]   # file name, and the folder it sits in
2-element Vector{String}:
 "fig.png"
 "/a/b"

落とし穴の例：エクスプローラのパスをそのまま貼ると

Windows のエクスプローラでパスをコピーすると C:\Users\you\Documents のような形で得られる． これを そのまま "..." の中に入れると，Julia は受け付けない．

次のコードは 実行できない．セルとして置いていないのは， 動かす前の 読み込む段階 でエラーになるからである．

x = "C:\Users"
ERROR: ParseError:
# Error @ none:1:8
x = "C:\Users"
#      └┘ ── invalid unicode escape sequence

"..." の中の \ は「次の文字と組にして特別な意味を表す」合図 である． \n が改行を表すのと同じ仕組みで，\U は「これから文字コードを書く」という合図になる． \Users の U がそれに取られてしまい，文字コードが続かないので壊れる．

直し方は3つある．

[raw"C:\Users", "C:\\Users", "C:/Users"]   # three ways that all work
3-element Vector{String}:
 "C:\\Users"
 "C:\\Users"
 "C:/Users"
  • raw"..." … \ を特別扱いしない書き方．貼り付けたパスをそのまま使える
  • "C:\\Users" … \ を2つ重ねて「\ という文字そのもの」を表す
  • "C:/Users" … / で書く．Windows の Julia は / でも正しく扱う

この資料では / で書くか，joinpath に任せる ことを勧める．\ を自分で書く場面をなくせる．

ファイルに書く

open(fn, "w") は，ファイル名 fn のファイルを 作って，書き込む準備をする． fn が既にあっても構わない．その場合，元の中身は捨てられる．

open が返す f を println(f, s) の 第1引数 に渡すと，文字列 s をそのファイルに1行書く． 第3回で使った println(x) は画面に書いたが，println(f, x) は ファイルに書く．

書き終わったら close(f) を呼ぶ．これを忘れると，中身が書かれないことがある．

f = open("hello1.txt", "w")    # create (or empty) the file
println(f, "Hello")            # write one line
println(f, "again.")           # and another
close(f)                       # finish writing

書いたら確かめる

第3回まで，実行結果は必ず 既知の答えと照合してきた．ファイルでも同じである． ここでの既知の答えは 自分が書いた2行 である．

まず，ファイルが本当に出来たかを見る．

isfile("hello1.txt")           # does it exist now?
true

次に，読み戻して中身を見る．eachline(fn) は，ファイルの中身を 1行ずつ 取り出す． for でそのまま走査できる（行末の改行は取り除かれている）．

for line in eachline("hello1.txt")    # read it back, line by line
    println(line)
end
Hello
again.

書いた2行がそのまま出てくれば一致している．行の 配列 が欲しいときは readlines を使う．

readlines("hello1.txt")        # the lines as an array of strings
2-element Vector{String}:
 "Hello"
 "again."
ノート画面の外でも確かめる

ここまでは Julia の中だけで確かめた．計算機のほうからも確かめておきたい．

Windows のエクスプローラを開き，pwd() が表示した場所に hello1.txt が出来ていることを確かめよ． 「メモ帳」で開き，書いたとおりの2行が入っていることを目で見よ． （macOS なら「ファインダー」と「テキストエディット」に読み替える）

プログラムの外から同じものが見えることを一度確認しておくと， 以降「ファイルが出来ない」で悩む時間が大きく減る．

close を忘れない書き方

open と close は 対で使う．間でエラーが起きると close に到達せず，中身が残らないことがある． これを避ける書き方がある．

open("hello2.txt", "w") do g   # close is called automatically at `end`
    println(g, "one")
    println(g, "two")
end

readlines("hello2.txt")        # check: did it get written?
2-element Vector{String}:
 "one"
 "two"

end まで来ると close(g) が自動で呼ばれるので，書き忘れが起きない． do ... end の仕組み自体（関数に処理を渡している）は 第13回で扱う． ここでは 「close を忘れない書き方」 として覚えておけばよい．

書式をそろえて表示する

誤差や計算結果を並べるとき，println だけでは 桁がそろわない． 桁をそろえるには標準ライブラリの Printf を使う．

using Printf

for n in (10, 100, 1000)
    @printf("n = %6d   1/n = %10.6f\n", n, 1/n)   # width 6 integer, width 10 with 6 decimals
end
n =     10   1/n =   0.100000
n =    100   1/n =   0.010000
n =   1000   1/n =   0.001000

%6d は「整数を幅6で」，%10.6f は「小数を幅10・小数点以下6桁で」という指定である． \n が改行で，@printf は自分では改行しないので，必要なら書く．

値を 文字列として 受け取りたいときは @sprintf を使う（s は string の s）．

s = @sprintf("%8.3e", 1/3)     # 8 wide, scientific with 3 decimals
"3.333e-01"
警告落とし穴の例：書式と引数の数が合わないと

% の個数と，後ろに渡す値の個数は 合っていなければならない． 次のセルは何が起こるだろうか．

@errmsg @printf("%d %d\n", 1)     # two specifiers, but only one value
ArgumentError: Number of format specifiers and number of provided args differ: 2 != 1

数が合わないと その場でエラーになる．黙って変な値が出るのではないので，気付きやすい．

理由は，図に漢字を入れると 黙って豆腐（□）になることがあるからである． エラーが出ないので，提出したあとで気付くことになる．

plot([1, 2, 3], [1, 4, 9], title = "time vs distance", xlabel = "time", ylabel = "distance")

この資料で扱わなかったこと

ファイルやフォルダを操作する関数は他にもあるが，ここでは わざと扱わない．

  • cd()（居る場所を移動する） … 呼ぶと，それ以降のセルで相対パスの意味が変わる． notebook を上から実行し直したときに 結果が変わってしまう． この教材は「同じ手順なら同じ結果になる」ことを検証の土台にしているので，それを崩す道具は使わない． 移動する代わりに，pwd() で場所を確かめて joinpath で指す．
  • rm（ファイルを消す）など … 取り返しがつかない． 間違えて配布 notebook やレポートを消すほうが，学べることより大きい． ファイルを消すときは エクスプローラ（ファインダー） で行う．

まとめ

  • ファイルを触る前に pwd()．いま居る場所が，フォルダ名なしのファイル名の意味を決める．
  • readdir() で，いま居る場所の中身が見える．notebook のファイル名があれば同じ場所に居る．
  • パスは joinpath で組み立てる．区切り文字（\ か /）を自分で書かない．
  • 落とし穴："C:\Users" は \U が特別な意味に取られて 読み込む段階でエラー． raw"..."／"\\"／"/" のどれかにする．この教材は / と joinpath を勧める．
  • 書き込みは open(fn, "w") → println(f, s) → close(f)．do ... end なら close を忘れない．
  • 読み込みは eachline(fn)（1行ずつ）か readlines(fn)（配列で）．open は要らない．
  • 書いたら 確かめる：isfile で存在を，読み戻しで中身を．さらに エクスプローラとメモ帳でも見る．
  • 桁をそろえて表示するには using Printf と @printf／@sprintf．% の数と値の数を合わせる．
  • 図の中の文字は英語．漢字は Markdown セルの文章に書く．
