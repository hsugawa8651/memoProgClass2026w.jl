第15回：複素数とガウス平面

今回は 複素数 を学び，それを平面上の点とみなす ガウス平面 を描く． 回転は複素数では z に cis(θ)=e^{iθ} を掛ける という，もっとも短い1行で表せる． キーワードは 「回転とは，絶対値を変えずに偏角を足すこと」．

ノート回転は3度現れる

同じ「回転」が，この教材では 3つの姿 で現れる．

  • 第5回：座標ごとの式で回す（ブロードキャスト）
  • 第14回：回転行列 R(θ) の掛け算1つにまとめる
  • 第15回：複素数 z * cis(θ) の掛け算1つで書く　← いまここ

第15回で，3つが同じ回転であることを1つの点で確かめる． 同じ考えが道具を変えて現れるところが，この教材の見どころである．

複素数を作る

複素数は，実部と虚部を渡して complex(1, 2) と作れる（実部 1，虚部 2 の複素数）．

z = complex(1, 2)
1 + 2im

im（虚数単位，2乗すると \(-1\)）を使って 1 + 2im と書いてもよい（リテラル形）． どちらも同じ値になる．変数から作るときは a + b*im と *im が要るので， complex(a, b) のほうが読みやすいことが多い．場面で選べばよい．

1 + 2im              # literal form: same complex number (real 1, imag 2)
1 + 2im
ノート

2im は「2 と im の掛け算」を意味する．数学では虚数単位を \(i\) と書くが， Julia では i をループ変数などに使うことが多いため，混同を避けて im を使う．

実部・虚部・共役・絶対値・偏角

複素数からは，いくつもの 属性 を取り出せる．

  • real(z)：実部（横方向の成分）
  • imag(z)：虚部（縦方向の成分）
  • conj(z)：共役複素数（虚部の符号を反転）
  • abs(z)：絶対値（原点からの距離＝長さ）
  • angle(z)：偏角（実軸となす角，ラジアン）
z = complex(1, 2)
real(z), imag(z)     # the real and imaginary parts
(1, 2)
conj(1 + 2im)        # the conjugate
1 - 2im
重要実行する前に予測しよう（L1）

abs(1 + 1im) と angle(im) はいくつになるか？ 1 + 1im は点 \((1, 1)\)，im は点 \((0, 1)\) にあると考えてみよう．

abs(1 + 1im), angle(im)     # length and argument
(1.4142135623730951, 1.5707963267948966)

点 \((1,1)\) の原点からの距離は \(\sqrt{1^2+1^2}=\sqrt{2}\)， 点 \((0,1)\) の偏角は実軸から \(90°=\pi/2\) である． abs は長さ，angle は角度．この2つが今回の主役になる．

落とし穴：負の数の平方根

実数の世界では「2乗して \(-1\) になる数」は存在しない． では，実数の -1 を sqrt に渡すと，どうなるだろうか．

重要予測しよう（L1）

sqrt(-1) は何を返すか？ 計算できるか，それともエラーか？

@errmsg sqrt(-1)        # square root of a negative real number
DomainError with -1.0:
sqrt was called with a negative real argument but will only return a complex result if called with a complex argument. Try sqrt(Complex(x)).
警告落とし穴：実数領域では例外になる

sqrt に 実数の -1 を渡すと，「実数の範囲では答えがない」ため例外になる． これは型の落とし穴である：同じ式でも，渡す数の型（実数か複素数か）で結果が変わる．

引数を 複素数 -1 + 0im にすれば，複素数の世界で計算でき，im が返る．

sqrt(-1 + 0im)      # the same, but with a complex argument
0.0 + 1.0im

一方，(-1)^0.5 も 実数のべき乗 として扱われ， 答えが実数にならないため，sqrt(-1) と同じく DomainError になる．

@errmsg (-1)^0.5            # a real power that would leave the reals
DomainError with -1.0:
Exponentiation yielding a complex result requires a complex argument.
Replace x^y with (x+0im)^y, Complex(x)^y, or similar.
ノートまとめ：負の数の平方根は「複素数にする」と計算できる
  • sqrt(-1)（実数）→ DomainError（例外）
  • (-1)^0.5（実数べき乗）→ DomainError（sqrt(-1) と同じ理由）
  • sqrt(-1 + 0im)（複素数）→ im（計算できる）

「引数を複素数にすれば計算できる」というのは，AI に修正を頼むときの定石でもある．

落とし穴：複素数を < で比べる

実数は数直線の上に並ぶので < で比べられる． 複素数は 平面 に散らばっているが，< ではどうなるだろうか．

重要予測しよう（L1）

(1 + 2im) < (3 + 4im) は true になるか，それともエラーか？

@errmsg (1 + 2im) < (3 + 4im)       # comparing two complex numbers with <
MethodError: no method matching isless(::Complex{Int64}, ::Complex{Int64})
The function `isless` exists, but no method is defined for this combination of argument types.

Closest candidates are:
  isless(::Missing, ::Any)
   @ Base missing.jl:87
  isless(::Any, ::Missing)
   @ Base missing.jl:88
  isless(::Missing, ::Missing)
   @ Base missing.jl:86
  ...
警告落とし穴：複素数は並べられない

「絶対値で比べているのだろう」と思い込むと誤る．Julia は 複素数そのものの < を拒否 する． 大きさで比べたいなら abs(z1) < abs(z2) のように 絶対値にしてから 比べる．

ガウス平面：複素数を平面に描く

複素数 a + b*im を点 \((a, b)\) とみなして平面に描いたものを ガウス平面（複素平面）という． 横軸が実部，縦軸が虚部である．まずは図を描くために Plots を読み込む （先頭の準備セルで読み込み済みだが，作法として確認する）．

using Plots

複素数のベクトルから，real.／imag.（ブロードキャスト） で \(x\) 座標・\(y\) 座標のベクトルを取り出し，plot に渡す． 第5回で座標ベクトルで描いた図形を，今度は 複素数の頂点 で表してみよう．

zs = [0+0im, 2+0im, 2+1im, 0+1im, 0+0im]   # rectangle vertices (complex)
plot(real.(zs), imag.(zs), aspect_ratio=:equal)
ノートアスペクト比＝1（第5回が効く）

aspect_ratio=:equal は，横と縦の 目盛りの間隔をそろえる 指定である（第5回）． ガウス平面は 等方的（どの向きも同じスケール）なので，これを付けないと 回転や長さが歪んで見える．長さ abs と角度 angle を正しく見るために必須である．

回転の複素数表現

複素数 z に cis(θ) を掛けると，原点まわりに角 θ だけ回転 する． ここで

\[ \operatorname{cis}(\theta) = \cos\theta + i\sin\theta = e^{i\theta} \]

である（cis は cos i sin の頭字語）． 点 \((1,0)\) を表す z = 1 + 0im を \(45° = \pi/4\) だけ回転させてみよう．

z = 1 + 0im        # point (1, 0)
z * cis(π/4)       # rotate by 45°
0.7071067811865476 + 0.7071067811865475im
ノートなぜ cis(θ) が回転なのか

\(e^{i\theta} = \cos\theta + i\sin\theta\) を オイラーの公式 という． 右辺はガウス平面で 絶対値 1，偏角 \(\theta\) の点，つまり単位円上の点である． 絶対値1の数を掛けても長さは変わらず，偏角だけが \(\theta\) 増える．これが回転である．

cis(θ) と exp(im*θ) が同じ値であることは，その場で確かめられる．

[cis(π/3), exp(im*π/3)]       # the same point on the unit circle
2-element Vector{ComplexF64}:
 0.5000000000000001 + 0.8660254037844386im
 0.5000000000000001 + 0.8660254037844386im

回転の前後で 何が変わり，何が変わらないか を，abs と angle で確かめる．

重要予測しよう（L1）

z * cis(π/4) の 絶対値 と 偏角 はどうなるか？ ガウス平面で z と z * cis(π/4) がそれぞれどこにあるか，描いてから考えよう．

w = z * cis(π/4)
abs(z), abs(w)     # compare the two lengths
(1.0, 1.0)
angle(w)           # and the argument?
0.7853981633974483
ヒント回転とは「絶対値を変えず，偏角を足す」こと

z * cis(θ) は，長さ abs をそのままに，向き angle に θ を加える． これが回転の正体である．cis でなく誤った係数を掛けると abs まで変わってしまい， それは 回転ではなく拡大・縮小が混ざった操作 になる．

ガウス平面で図形を丸ごと回転

図形の頂点ベクトル zs を 丸ごと cis(θ) 倍すれば，図形全体が原点まわりに回る． スカラー倍なので，ドットは要らない（第2回の峻別）．

zr = zs * cis(π/6)             # vector times scalar: rotate all vertices 30 deg
plot(real.(zs), imag.(zs), aspect_ratio=:equal)   # before rotation
plot!(real.(zr), imag.(zr))                        # overlay after rotation

回転前後で，対応する頂点の 原点からの距離（abs）は変わらず， 全体が原点を中心に \(30°\) だけ傾いているのが見てとれる． これは第5回で xs .+ 2 として平行移動した発想（ブロードキャスト1つで図形を変換 する）を， 回転 にまで広げたものである．

回転の一本糸：3つの表現は同じ回転

最後に，このコースの 「回転の一本糸」 を1本に束ねよう． 点 \((x, y)\) を角 θ だけ回転する操作を，私たちは3通りの姿で見てきた．

  • 第5回（ブロードキャスト）：座標ごとに手書きの式 \[ x' = x\cos\theta - y\sin\theta,\quad y' = x\sin\theta + y\cos\theta \]
  • 第14回（回転行列）：\(\begin{pmatrix} x' \\ y' \end{pmatrix} = R(\theta)\begin{pmatrix} x \\ y \end{pmatrix}\)，ただし \(R(\theta)=\begin{pmatrix}\cos\theta & -\sin\theta \\ \sin\theta & \cos\theta\end{pmatrix}\)
  • 第15回（複素数）：\(z \mapsto z\,e^{i\theta} = z\,(\cos\theta + i\sin\theta)\)

この3つが まったく同じ回転 であることを，1つの点で確かめる．

重要予測しよう（L1）

点 \((2, 1)\) を \(30°\) 回転した結果は，3つの方法で 一致 するだろうか？

θ = π/6
x, y = 2.0, 1.0

# (1) Lesson 5: hand-written broadcast formula
xb = x*cos(θ) - y*sin(θ)
yb = x*sin(θ) + y*cos(θ)

# (2) Lesson 14: rotation matrix R(θ) * v
R = [cos(θ) -sin(θ); sin(θ) cos(θ)]
vm = R * [x, y]

# (3) Lesson 15: complex number z * cis(θ)
zc = (x + y*im) * cis(θ)

(xb, yb), (vm[1], vm[2]), (real(zc), imag(zc))
((1.2320508075688774, 1.8660254037844386), (1.2320508075688774, 1.8660254037844386), (1.2320508075688774, 1.8660254037844386))

3つが一致するかを確かめる．小数なので == ではなく ≈（第10回）で比べる． ≈ にドットを付けると，要素ごとに比べた結果が返る（第2回のブロードキャスト）．

# do the 3 representations agree (within rounding error)?
(xb, yb) .≈ (vm[1], vm[2]),  (xb, yb) .≈ (real(zc), imag(zc))
((true, true), (true, true))

今回のまとめ

  • 複素数 は complex(1, 2) または 1 + 2im（im は虚数単位）で作る．real／imag／conj／abs／angle で属性を取り出す．
  • 落とし穴：sqrt(-1) は実数では DomainError．sqrt(-1 + 0im) なら im．(-1)^0.5 も同じく DomainError．
  • 落とし穴：複素数に 順序（<）はない．大きさで比べるなら abs にしてから．
  • ガウス平面：a + b*im を点 \((a, b)\) に描く．等方なので アスペクト比＝1（第5回）が効く．
  • 回転 は z * cis(θ)：絶対値 abs は不変，偏角 angle が θ だけ増える．ブロードキャストで図形を丸ごと回せる．3通りの表現のうち，これが 掛け算1つ でもっとも短い．

ノート回転の一本糸を振り返って

第2回でブロードキャストを覚え，第5回で正方形の歪みを「アスペクト比」で直して座標を手書きの式で回し， 第14回でそれを行列 R(θ) の1つの掛け算に圧縮し，今回 複素数 z·e^{iθ} という最短の形に行き着いた． ひとつの「回転」という考えが，このコースを通して 何度も姿を変えながら 現れたことが， プログラミングで数学を扱うことの面白さである．

ヒント練習
  1. z = 3 + 4im について，abs(z) と angle(z) を予測してから確かめよ（abs は \(5\) になるはず）．
  2. 点 1 + 0im を cis(π/2)（\(90°\)）回転すると何になるか予測し，abs と angle で確認せよ．
  3. 自分で三角形などの頂点を複素数で決め，cis(θ) をブロードキャストして回転させ，回転前後を重ね描きせよ．
