第6回：条件分岐とはさみうち

今回の背骨は 条件分岐，すなわち「状況によって違うことをする」仕組みである． そのために，まず 比較演算と論理型 Bool，そして 論理演算（かつ・または・否定）を学び， それらを使って if 文 を書く． 仕上げに，はさみうち法（区間を半分にして根を挟みこむ方法）を ベタ書きで体験する． キーワードは 「条件で分かれ，同じステップを繰り返して挟みこむ」．

比較演算と論理型

比較演算子 は「左右の大小・等しさ」を調べ，その結果は数ではなく true（真） か false（偽） という 論理値（Bool 型）になる． true/false は第1回で顔見せ済みだが，今回が主役である．

3 < 5             # is 3 less than 5? → true
true
2 == 2            # equal? → true (== is comparison; = is assignment)
true

主な比較演算子は，<（より小さい），>（より大きい）， <=（以下，≤ とも書ける），>=（以上，≥ とも書ける）， ==（等しい），!=（等しくない）である．

2 <= 2            # is 2 less than or equal to 2? → true
true
3 ≤ 5             # ≤ is the same as <= (type \le then Tab)
true
重要予測しよう（L1）

0.1 + 0.2 == 0.3 は true だろうか．実行する前に予想しよう．

0.1 + 0.2 == 0.3
false

false になる．小数はコンピュータ内部（浮動小数点数）では ぴったりは表せず，わずかな誤差を含むためである． くわしくは第10回（浮動小数点と数値誤差）で扱う． 今は「小数どうしを == で厳密に比べない」とだけ覚えておけばよい．

発展：連鎖比較

ノート

ここは 発展（必修ではない）．読み飛ばして，次の 「論理演算」 へ進んでよい．

Julia では数学と同じように，比較を 連ねて書ける． 1 < 3 < 5 は「1 < 3 かつ 3 < 5」の意味になる．

重要予測しよう（L1）

1 < 3 < 5 は何になるか？ また 5 < 3 < 1 はどうか？

1 < 3 < 5         # chained comparison
true
5 < 3 < 1         # and this one?
false

「a < x < b（x が a と b の間にあるか）」のように， 範囲に入っているかの判定 によく使う．

論理演算：かつ・または・否定

複数の条件を 組み合わせる には 論理演算子 を使う．

  • && … かつ（and）：両方が true のときだけ true．
  • || … または（or）：どちらか一方でも true なら true．
  • ! … 否定（not）：true と false を入れ替える．
true && false     # and: false unless both are true
false
true || false     # or: true if either one is true
true
!true             # not: true ↔ false
false

比較と組み合わせると，意味のある判定が書ける．

重要予測しよう（L1）

x = 7 のとき，(x > 0) && (x < 10) と (x < 0) || (x > 5) は何になるか？

x = 7
(x > 0) && (x < 10)   # positive and less than 10 → true
true
(x < 0) || (x > 5)    # negative or greater than 5 → true
true
警告落とし穴：&& と & は別物

条件をつなぐ「かつ」は &&（2つ重ねる） を使う． &（1つ）はビット演算という別の演算で，意味も挙動も違う． 論理の「かつ・または」は &&・|| と覚えること．

if 文：条件で枝分かれ

if 文 を使うと，条件が true のときと false のときで 違う処理を実行できる．基本形は if … elseif … else … end である． 上から順に条件を調べ，最初に true になった枝だけを実行する．

println には，" で囲んだ 文字列（文字の並び）も渡せる．

x = 7
if x > 0
    println("positive")
elseif x < 0
    println("negative")
else
    println("zero")
end
positive

x が 7 なので最初の条件 x > 0 が true となり，positive が表示される． println は値を画面に出力する命令である（戻り値は使わない）．

重要予測しよう（L1）

上の x を 0 や -3 に変えたら，何が表示されるか予測してから確かめよう．

警告落とし穴：=（代入）と ==（比較）の混同

条件には 比較の == を使う．if x = 5 のように 代入の = を書くと， 意図（「x が 5 か？」）と違う意味になり，エラーや誤動作のもとになる． = は代入，== は比較．第1回からの鉄則である．

break：条件が成り立ったら繰り返しを抜ける

第3回の for は，用意した値を 最後まで 走査する． しかし「もう続ける必要がない」と途中で分かることがある． そのとき break を書くと，残りを飛ばしてループを抜ける． if と組み合わせて使う．

重要予測しよう（L1）

次のループは，xs のどこまで見て止まるか．何が表示されるか．

xs = [3, 8, 12, 5, 20]
for x in xs
    println(x)
    if x > 10
        break           # stop as soon as the condition holds
    end
end
3
8
12

最初に 10 より大きい値（12）に出会った時点で抜けるので，5 と 20 は見ない． 「全部見る」のか「見つけたら止める」のかは，書き手が決めることである．

ノート止まることを確かめる

break は便利だが，抜ける条件が一度も成り立たないと，ループは最後まで回る （for なので，いずれ必ず終わる）． 回数が決まらない繰り返し（while）では，これが 止まらない という事故になる． 第9回と第12回で，止まる理由を確かめながら扱う．

ノート補足：アルゴリズム図に「分岐の箱」を足す

第3回で 反復（くり返し）の箱 を図に描いた．今回 分岐の箱 が加わり， 逐次，反復，分岐という 3つの制御構造 がそろう． 教材の図は Excalidraw（手描き）で提示する． 図は，自分の考えを整理するために描く．提出はコードと説明でよい． 大事なのは「コードが図のとおりになっているか」を見比べることである．

はさみうち法をベタ書きで体験

方程式 \(f(x)=0\) の解（根）を，区間を半分ずつ狭めて追いつめる方法を はさみうち法（二分法）という． ここでは \(f(x)=x^2-2\) の正の根，すなわち \(\sqrt{2}\) を挟みこむ．

考え方は単純である．根を含む区間 \([a, b]\) の 中点 \(c\) で \(f(c)\) の 符号を調べ， 根がある側の半分に区間を取り替える．これを繰り返すと区間がどんどん縮む．

重要はさみうちの前提：端点で符号が異なること

出発の区間 \([a, b]\) は，端点で \(f\) の符号が逆でなければならない （\(f(a)<0\) かつ \(f(b)>0\)，など）．まずそれを確かめる．

a, b = 1.0, 2.0       # both ends at once (simultaneous assignment, lesson 5)
a^2 - 2               # f(a) = f(1) → negative (< 0)
-1.0
b^2 - 2               # f(b) = f(2) → positive (> 0)
2.0

符号が逆なので，区間 \([1.0, 2.0]\) の中に根がある．では 1ステップやってみる． 中点 \(c\) をとり，両端と中点の符号の積 \(f(a)\cdot f(c)\) を見て，根がある半分に区間を狭める．

重要予測しよう（L1）

中点 \(c=1.5\) で，\(f(a)\cdot f(c)\) の符号はどうなるか？ （\(f(a)=1^2-2<0\)，\(f(c)=1.5^2-2\)）． それに応じて，次の区間は \([1.0, 1.5]\) と \([1.5, 2.0]\) のどちらになるか予測しよう．

a, b = 1.0, 2.0          # interval with f(a)*f(b)<0 (signs differ at the two ends)
c  = (a + b) / 2         # midpoint
fa = a^2 - 2             # f(a)
fc = c^2 - 2             # f(c)
if fa * fc < 0
    b = c                # signs differ on [a, c] → root is in [a, c] → move right end to c
else
    a = c                # otherwise the root is in [c, b] → move left end to c
end
[a, b]                   # interval has shrunk by half
2-element Vector{Float64}:
 1.0
 1.5

\(f(1.0)\cdot f(1.5) = (-1)\times 0.25 < 0\) なので 真の枝に入り，右端が \(1.5\) になって区間は \([1.0, 1.5]\) に縮む． \(\sqrt{2}\approx 1.414\) は，ちゃんとこの中に入っている．

この「中点をとる → \(f(a)\cdot f(c)\) の符号を見る → 区間を半分にする」という1ステップを図にすると 図 1 のようになる．

ノート補足：同じステップを「くり返したい」

いま書いた「中点をとる → 符号を見る → 区間を半分にする」は， まったく同じ手順をもう一度やれば，さらに区間が縮む． このコードを そのままコピーして続けてみよう（手で数回回す）．

a, b = 1.0, 2.0
# --- step 1 ---
c = (a + b) / 2
fa = a^2 - 2
fc = c^2 - 2
if fa * fc < 0
    b = c
else
    a = c
end
println("step 1: [", a, ", ", b, "]  width = ", b - a)
# --- step 2 (copy the same procedure) ---
c = (a + b) / 2
fa = a^2 - 2
fc = c^2 - 2
if fa * fc < 0
    b = c
else
    a = c
end
println("step 2: [", a, ", ", b, "]  width = ", b - a)
# --- step 3 (same procedure again) ---
c = (a + b) / 2
fa = a^2 - 2
fc = c^2 - 2
if fa * fc < 0
    b = c
else
    a = c
end
println("step 3: [", a, ", ", b, "]  width = ", b - a)
step 1: [1.0, 1.5]  width = 0.5
step 2: [1.25, 1.5]  width = 0.25
step 3: [1.375, 1.5]  width = 0.125

回すたびに 区間の幅が半分になり，\(\sqrt{2}\) をだんだん細かく挟みこんでいく．

sqrt(2)               # check the answer: the interval brackets this value
1.4142135623730951
警告落とし穴：端点が同符号だと破綻する

もし出発の区間が 同符号（たとえば \(f(a)\) も \(f(b)\) も正）だったら， 「符号が変わる場所」が区間内にあるとは限らず， はさみうちは 偽の答えに収束したり破綻したりする． 始める前に端点の符号を確認する．これが前提である．

ノート補足：「同じ手順の繰り返し」を括り出したい（第7回への伏線）

上で 同じコードを3回コピーしたのが気になっただろう． 「同じステップを何度も繰り返すなら，ひとまとめにして名前を付けたい」． これが 関数の発想である． 次回（第7回）では，このはさみうち1ステップを 関数として括り出す．

今回のまとめ

  • 比較演算（<，>，==，<=/≤ など）の結果は 論理型 Bool（true/false）．
  • 小数の == は信用しない：0.1 + 0.2 == 0.3 は false（浮動小数点の誤差，第10回）．
  • （発展）連鎖比較 a < x < b は「a<x かつ x<b」．
  • 論理演算 &&（かつ）・||（または）・!（否定）で条件を組み合わせる（& とは別物）．
  • if 文 if … elseif … else … end は，最初に true になった枝だけを実行する（= と == を混同しない）．
  • はさみうち法：端点で符号が逆の区間 \([a,b]\) から，両端と中点の符号の積 \(f(a)\cdot f(c)\) で根のある半分を選んで狭めるのを繰り返し，根を挟みこむ（同符号は落とし穴）．
