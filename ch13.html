第13回：関数の作り込み

今回は，これまで後回しにしてきた 関数の機能 を学ぶ． 必修は 既定値引数・複数戻り値（タプル）・高階関数（関数を引数にとる） の三つで， キーワードは 「関数は値である」 こと．第12回の数値積分 trapezoid を 「積分する関数 f を引数にとる」形に一般化して，関数化の 完成形 を作る． 最後に，これらと第6回の 条件分岐（if） を組み合わせた応用として， モンテカルロ法で面積（円周率） を推定する．再帰 は発展として扱う．

既定値引数

引数に = で 既定値 を与えると，その引数を 省略して呼べる． 省略すると既定値が使われる．

power(x, n=2) = x^n
power (generic function with 2 methods)

n を省略すると n=2（2乗）になる．n を渡せばその値が使われる．

重要予測しよう（L1）

power(3) と power(3, 3) はそれぞれいくつになるか，実行する前に予想しよう．

power(3)       # n omitted: which n is used?
9
power(3, 3)    # n given explicitly
27
ノート

既定値引数は「よく使う設定を省略できるようにする」ための仕組みである． 第12回の台形則も，分割数 n に既定値を与えておけば， ふだんは n を省いて呼べるようになる（この章の後半で書き直す）．

複数戻り値とタプル

関数は 値をひとつだけ返すのが基本だが，いくつかの値をまとめて返すこともできる． そのまとめ役が タプル（( ) でくくった並び）である．

たとえば組み込みの divrem(a, b) は，第9回の div（商）と rem（余り）を一度に行い， 2つの結果をタプルで同時に返す．

重要予測しよう（L1）

divrem(17, 5) は何を返すか？（17 を 5 で割った 商 と 余り）

divrem(17, 5)      # tuple of (quotient, remainder)
(3, 2)

返ってきたタプルは，左辺に同じ個数の名前を並べて一気に受け取れる． これを 分解代入 という．

q, r = divrem(17, 5)
q
3
r
2

同時代入の正体

第5回の 同時代入 x, y = y, x は，実はこのタプルの働きである． 右辺の y, x がまずタプルになり，それが左の2つの名前へ配られる． 第9回の互除法 a, b = b, rem(a, b) も同じ仕組みだった．

タプルに名前が付いたことで，関数から2つの値を返すことができるようになる．

同じ型の関数に sincos(θ) がある．正弦と余弦を 一度に 計算して組で返す． 第5回の回転のように両方を使うときは，これで1回の呼び出しで済む．

s, c = sincos(π/6)      # sine and cosine at once
[s, c]
2-element Vector{Float64}:
 0.49999999999999994
 0.8660254037844387

自分の関数からタプルを返すには，return (a, b) のように書く（( ) は省略してもよい）． 次の minmax2 は，二つの数を 小さい順のタプルにして返す．

function minmax2(a, b)
    if a < b
        return (a, b)
    else
        return (b, a)
    end
end
minmax2 (generic function with 1 method)
minmax2(5, 3)      # which order comes back?
(3, 5)
minmax2(3, 5)      # and this one?
(3, 5)
警告落とし穴：分解代入で値が足りないとエラー

右辺のタプルの要素が，左辺の名前の個数より 少ない とエラーになる． たとえば a, b, c = (1, 2) は，3個の名前に2個の値しかなく失敗する （逆に，値の方が 多い ときは余りが無視され，エラーにはならない）．

@errmsg begin a, b, c = (1, 2) end   # 3 names, 2 values (too few) -> error
BoundsError: attempt to access Tuple{Int64, Int64} at index [3]

高階関数：関数を引数に渡す

Julia では 関数も値である．数や文字列と同じように，関数を引数として別の関数に渡せる． このような「関数を受け取る／返す関数」を 高階関数 という．

第12回で作った台形公式 trapezoid を，積分したい関数 f を引数にとる形に一般化しよう． a，b は積分区間，n は分割数（既定値 100）である．

function trapezoid(f, a, b, n=100)     # f is an argument, n has a default
    h = (b - a) / n
    s = (f(a) + f(b)) / 2
    for k in 1:n-1
        s += f(a + k*h)
    end
    return s * h
end
trapezoid (generic function with 2 methods)

x -> x^2 のような 無名関数（その場限りの名無し関数）を渡せば，\(\int_0^1 x^2\,dx = 1/3\) を数値計算できる．

重要予測しよう（L1→L2：既知の値と照合）

\(\displaystyle\int_0^1 x^2\,dx = \frac13 \approx 0.3333\) である． 下の結果はこれに近いか，実行前に見当をつけよう．

trapezoid(x -> x^2, 0, 1)      # ∫₀¹ x² dx = 1/3 ≈ 0.3333
0.33335000000000004

同じ trapezoid に，組み込みの sin をそのまま渡せる（f に名前で渡すだけ）． \(\displaystyle\int_0^\pi \sin x\,dx = 2\) と照合できる．

trapezoid(sin, 0, π)           # ∫₀^π sin x dx = 2
1.9998355038874436
ノート

trapezoid の中身は 一切変えていない のに， 渡す f を変えるだけで どんな関数でも積分できる． これが「関数を値として渡す」高階関数の威力であり， 第12回からの 関数化の完成形 である．

ヒント

関数を引数で渡すと，処理の「中身」を後から差し替えられる． trapezoid は「積分の手続き」だけを書き，「何を積分するか」は呼ぶ側が決める．

発展：再帰（自分自身を呼ぶ）

ノート

ここから（再帰）は 発展（必修ではない）．関数が自分自身を呼ぶという新しい考え方で， 呼び出しが積み上がる（スタック）しくみの理解が要る．読み飛ばして，次の 「モンテカルロ法で面積（円周率）を推定する」 へ進んでよい．

関数の定義の中で，その関数自身を呼ぶ ことができる．これを 再帰 という． 再帰には 必ず基底ケース（それ以上は再帰せず，直接答えを返す場合）が要る．

階乗 \(n! = n \times (n-1)!\) は，基底 \(0! = 1\) をもつ典型的な再帰である．

ノート1行で書く ? :

下の定義に出てくる 条件 ? A : B は，条件が真なら A，偽なら B という式である （三項演算子 という）．if … else … end を1行に縮めた書き方で， 再帰のように「基底ケースか，そうでないか」を書き分けるときによく使われる．

fact(n) = n == 0 ? 1 : n * fact(n-1)      # base case: fact(0) = 1
fact (generic function with 1 method)
重要予測しよう（L1）

fact(5) はいくつか？（\(5! = 5\times4\times3\times2\times1\)）

fact(5)        # check against your prediction
120

fact(3) の呼び出しは，次のように 展開（トレース）できる．

\[ \begin{aligned} \texttt{fact(3)} &= 3 \times \texttt{fact(2)} \\ &= 3 \times (2 \times \texttt{fact(1)}) \\ &= 3 \times (2 \times (1 \times \texttt{fact(0)})) \\ &= 3 \times (2 \times (1 \times 1)) \\ &= 6 \end{aligned} \]

最後の fact(0) が 基底ケース で，ここで 1 を返して止まる．

フィボナッチ数列 \(F_n = F_{n-1} + F_{n-2}\)（\(F_0=0,\ F_1=1\)）も再帰で書ける．

fib(n) = n < 2 ? n : fib(n-1) + fib(n-2)
fib (generic function with 1 method)
fib(10)        # F10 by hand?
55
警告落とし穴（その1）：基底ケースを忘れると止まらない

while に止まる理由が要る（第9回・第12回）のと同じことが，再帰にも要る． もし fact から基底ケースを抜いて

fact_bad(n) = n * fact_bad(n - 1)    # no base case -> never stops!

と書くと，n は \(0\) を素通りして \(-1, -2, \dots\) と どこまでも小さくなり， 関数呼び出しが 無限に積み上がって やがて スタックオーバーフロー（stack overflow）で異常終了する． 再帰には基底ケースが必須である． （このコードは危険なので，このノートでは 実行しない．）

# Dangerous: no base case, so infinite recursion -> stack overflow
fact_bad(n) = n * fact_bad(n - 1)
fact_bad(5)        # never stops (do not run!)
警告落とし穴（その2）：naive な Fib は指数爆発する

上の fib は，fib(n-1) と fib(n-2) の中で 同じ値を何度も計算し直す． たとえば fib(5) を求める途中で fib(2) が何回も現れる． このため計算量は 指数的に増える． fib(10) は一瞬だが，fib(45) では数秒かかり，fib(50) では分単位になる． n を少し増やすだけで爆発的に遅くなる． （速く求めるには，前の2つの値をためていく 反復（第3回の足しこみ）で書けばよい．）

# Slow on purpose: fib(45) takes seconds, fib(50) takes minutes
fib(45)

発展：計算した値を覚えておく（メモ化）

ノート

ここから先は 発展（必修ではない）． 読み飛ばして，次の モンテカルロ法 へ進んでよい．

fib が遅いのは，同じ値を何度も計算し直すからだった． ならば 一度計算した答えを覚えておき，次は覚えたものを返せばよい．これを メモ化 という．

覚えておく入れ物には Dict（辞書） を使う． 配列の添字は 1, 2, 3, … の整数に限られるが，辞書は 「キー → 値」の対応 を好きに作れる．

memo = Dict(0 => 0, 1 => 1)        # key => value: fib(0)=0, fib(1)=1 are known
memo[0]                            # look up by key
0

haskey(memo, n) で「そのキーを覚えているか」を調べ，覚えていなければ計算して memo[n] = … で書き込む．

function fib_memo(n)
    if haskey(memo, n)             # already computed?
        return memo[n]
    end
    value = fib_memo(n-1) + fib_memo(n-2)
    memo[n] = value                # remember it for next time
    return value
end
fib_memo (generic function with 1 method)
fib_memo(45)                       # returns at once (the naive fib never would)
1134903170

同じ fib(45) が一瞬で返る． 再帰の形は変えず，覚えておくという一手だけで指数爆発が消えた．

モンテカルロ法で面積（円周率）を推定する

最後に，既定値引数・タプル分解・乱数 に，第6回の 条件分岐（if） を組み合わせた 応用として，モンテカルロ法 で面積（円周率 \(\pi\)）を推定する．

正方形 \([0,1)\times[0,1)\) に一様乱数で点を打ち，単位円の内側 \(x^2+y^2<1\) に入ったか を if で判定して数える．面積比は \(\dfrac{\pi/4}{1} = \dfrac{\pi}{4}\) なので， 内側の割合を4倍すれば \(\pi\)（＝四分円の面積×4）の推定値になる．

下のループの for _ in 1:n の _ も 変数名 である． 何回目かを本体で使わないときに，_ という名前にしておくと 「この値は使わない」ことが読み手に伝わる（for i in 1:n と書いても動く）．

function monte_pi(n = 10^5)
    inside = 0
    for _ in 1:n
        x, y = rand(), rand()        # random in [0,1) (tuple unpacking)
        if x^2 + y^2 < 1             # inside the unit circle? (lesson 6 conditionals)
            inside += 1              # count one if inside
        end
    end
    return 4 * inside / n
end
monte_pi (generic function with 2 methods)

rand() は実行のたびに違う乱数を返すので，結果は毎回少しずつ変わる． \(\pi \approx 3.14159\ldots\) に近い値になればよい．

monte_pi()      # default n=10^5; should be close to pi ~ 3.14...
3.1368

n を増やすほど推定は安定するが，誤差は \(1/\sqrt{n}\) でしか減らない（点を100倍にしても誤差は約10分の1にしかならない）．

monte_pi(10^6)  # n times 10; a bit more stable
3.142416
ノート同じ結果を再現したいとき

毎回変わると，誰かに結果を見せて確かめてもらうことができない． 種（seed） を固定すると，同じ乱数の列が再現できる．

using Random
Random.seed!(1234)       # fix the seed; the same sequence follows

バグを追うときや，結果を人と突き合わせるときは，まず種を固定する． 再現できることは，検証の前提である．

警告落とし穴：少ない試行で値を断定しない

モンテカルロ法の誤差は \(1/\sqrt{n}\) でしか減らない． 試行回数 n が少ないうちは推定値が大きくばらつくので， 少ない n の結果だけで「\(\pi\) はこの値だ」と断定してはいけない． 桁を一つ増やすには，n をおよそ 100倍 にする必要がある．

今回のまとめ

  • 既定値引数 f(x, n=2)：その引数を省略して呼べる（省略時は既定値）．
  • 複数戻り値は タプル (a, b) で返し，分解代入 q, r = divrem(17, 5) で受け取る．個数が合わないとエラー．
  • 高階関数：関数も 値なので，trapezoid(f, a, b) のように 関数を引数に渡せる．中身を変えずに「何をするか」を差し替えられる．
  • モンテカルロ法：乱数と if（第6回の条件分岐）で，単位円の内側に入った割合から 面積（\(\pi\)） を推定．誤差は \(1/\sqrt{n}\) でしかゆっくり減らない．
  • L2検証：trapezoid(sin, 0, π) を既知積分 2 と照合．monte_pi() が \(\pi\) に近づくかは 収束の様子 で見る（L3）．
  • （発展）再帰は自分自身を呼ぶ．基底ケースが必須（無いと stack overflow），naive な fib は 指数爆発する．
