第12回：反復の設計と数値積分

今回の背骨は，「いつ止めるか」を自分で設計する反復である． これまでの for は「決まった回数」回すループだったが， 今回は while ＋ break で「項が十分小さくなったら打ち切る」収束ループを書く． そして第7回の関数化を使って 数値積分（台形則） を関数にまとめ， 厳密解への収束と 誤差の減り方で検証する（L3）． あわせて，配列を一気に作る 内包表記 で，第2回からの配列の話を完成させる．

ノート今回のキーワード
  • 内包表記 [f(k) for k in …]：値の列を 一気に作る（ブロードキャストの仲間）．
  • 収束ループ：while ＋ break，許容誤差で打ち切る（総和＝第3回の発展）．
  • 数値積分（台形則）：和を関数にまとめ，厳密解 1/3 と照合．
  • 「止まる条件」を雑にすると 無限ループ（第10回・浮動小数点誤差の応用）．

内包表記：値の列を一気に作る

[式 for 変数 in 範囲] と書くと，範囲の各値について式を計算した配列ができる． これを 内包表記 という．第2回のブロードキャスト t .^ 2 の仲間で， 「値の列をひとかたまり（エンティティ）で作る」道具である．

重要予測しよう（L1）

[k^2 for k in 1:5] は何になるか，実行する前に予想しよう．

[k^2 for k in 1:5]                 # vary k from 1 to 5 and list k^2
5-element Vector{Int64}:
  1
  4
  9
 16
 25

配列の要素をすべて足すには sum を使う．sum([1, 2, 3]) は 6 である．

さらに，内包表記を sum に渡すときは 角括弧を省ける． sum(1/k^2 for k in 1:1000) は sum([1/k^2 for k in 1:1000]) と同じ結果で， 配列を作らずに足していくぶん無駄がない．

たとえば級数和 \(\displaystyle\sum_{k=1}^{1000} \frac{1}{k^2}\) は次のように書ける． これは有名な バーゼル問題の和で，項数を無限に増やすと \(\pi^2/6\) に近づく．

sum(1/k^2 for k in 1:1000)         # 1/1 + 1/4 + 1/9 + ... + 1/1000^2
1.6439345666815615
pi^2 / 6                           # reference (exact value)
1.6449340668482264
ノート

1000 項では小数第3位あたりで \(\pi^2/6\) とずれる． これは「まだ足し足りない」だけで，項を増やせば近づく． 「どこまで足せば十分か」を自分で決めて打ち切るのが，次の収束ループである．

収束ループ：許容誤差で打ち切る

第9回の互除法では，while の 止まる理由 がはっきりしていた （余りは必ず小さくなり，0 以上の整数だから）． 今回は 止まる理由が自明でない 場合を設計する．

while true … end は無限に回るループで，途中で break（第6回）に達すると抜ける． これを使えば，項 term が十分小さくなったら止める，という収束ループが書ける． 総和（第3回の s = s + x）の発展形である． なお，これから使う s += term は s = s + term の短い書き方である．

重要予測しよう（L1）

次のセルの s は，先ほどの sum(1/k^2 …) や \(\pi^2/6\) と 近い値になるだろうか？

s = 0.0
k = 1
while true
    term = 1/k^2
    s += term                      # accumulate (s = s + term)
    if term < 1e-10               # stop condition: term is small enough
        break
    end
    k += 1
end
s                                  # compare with pi^2/6
1.6449240669982403

打ち切りは if（第6回）で書き，条件が成り立ったら break で抜ける． 項 1/k^2 は \(k\) が増えるほど 単調に小さくなるから， いつか必ず 1e-10 を下回り，ループは確実に止まる．

ノート発展：&& を使った短い書き方（必修ではない）

term < 1e-10 && break と1行で書くこともある． && は 左が偽なら右を評価しない（短絡評価）ので，左が真のときだけ break に達する． 第6回では && を「条件をつなぐ かつ」として使ったが， 右側に 文 を置くこの書き方も，Julia のコードでよく見かける．

重要止まることを確かめよう（L2→L3）

term < 1e-10 で打ち切ると，\(1/k^2 < 10^{-10}\) すなわち \(k > 10^5\) で止まる． 許容誤差を厳しくすると項数は増えるが，有限回で必ず止まることを， tol を変えて確かめてみよう．

下のセルでは，文字列の中に $ を書いて変数の値を埋め込んでいる （"k = $k" は k の値に置き換わる）．これを 文字列補間 という．

for tol in [1e-8, 1e-10, 1e-12]
    s = 0.0
    k = 1
    while true
        term = 1/k^2
        s += term
        if term < tol
            break
        end
        k += 1
    end
    println("tol = $tol  ->  k = $k terms, stop,  s = $s")
end
tol = 1.0e-8  ->  k = 10001 terms, stop,  s = 1.6448340818460654
tol = 1.0e-10  ->  k = 100001 terms, stop,  s = 1.6449240669982403
tol = 1.0e-12  ->  k = 1000001 terms, stop,  s = 1.6449330668497701

許容誤差を厳しくする（tol を小さくする）ほど停止までの項数 k は増えるが， どれも有限回で止まっている．これが「設計された反復」である．

警告落とし穴：止まらない収束ループ（無限ループ）

次のコードは 絶対に実行してはいけない（レンダリングや REPL が固まる）． 打ち切りを !=（等しくない） で書くと，止まらないことがある． 0.1 は2進で正確に表せないので，0.1 を足し続けても x が ちょうど 1.0 になる瞬間はない． 条件 x != 1.0 は永久に成り立ち，無限ループになる．

s = 0.0
x = 0.0
while x != 1.0                # equality on floats: x never lands exactly on 1.0
    x += 0.1
    s += x
end                           # 0.1 is not exact in binary (do not run)

設計の鉄則は (1) 打ち切りに等号（==・!=）を使わない， (2) 反復上限（最大回数）も併せて設けることである． この例なら，不等号 x < 1.0 で打ち切る，回数を整数で数えて x = 0.1k と作る，など 直し方は一つではない． 第10回で見た「浮動小数点数には限界がある」という事実の，反復への応用である．

数値積分：台形則を関数にまとめる

定積分 \(\displaystyle\int_a^b f(x)\,dx\) は，区間を \(n\) 個の細い帯に切り， 各帯を 台形で近似して足し合わせると，おおよその値が求まる．これが 台形則である．

\[ \int_a^b f(x)\,dx \approx h\left(\frac{f(a)+f(b)}{2} + \sum_{k=1}^{n-1} f(a+kh)\right), \qquad h = \frac{b-a}{n} \]

両端 \(f(a),\,f(b)\) だけ 係数 \(1/2\)，内側の点は係数 \(1\) で足す，という形である． 第7回で学んだ 関数定義 function … end を使って，これを関数にまとめよう． ここでは積分する関数 f は 外で定義しておく（第7回の bisect のように引数で渡す形は，第13回で改めて整理する）．

f(x) = x^2                         # exact value: integral of x^2 from 0 to 1 = 1/3
function trapezoid(a, b, n)
    h = (b - a) / n
    s = (f(a) + f(b)) / 2          # endpoints get coefficient 1/2 (the key point)
    for k in 1:n-1
        s += f(a + k*h)            # interior points get coefficient 1 (accumulate)
    end
    return s * h
end
trapezoid(0, 1, 100)               # close to 1/3 = 0.3333...
0.33335000000000004
重要厳密解と照合しよう（L2）

\(\displaystyle\int_0^1 x^2\,dx = \left[\frac{x^3}{3}\right]_0^1 = \frac{1}{3}\) である． trapezoid(0, 1, 100) はこの 1/3 にどれだけ近いか確かめよう．

1/3                                # exact value
0.3333333333333333
abs(trapezoid(0, 1, 100) - 1/3)    # difference from exact value (= error)
1.6666666666720342e-5

発展：誤差の減り方と両対数グラフ

ノート

ここから先（誤差の 次数 と 両対数グラフ）は 発展（必修ではない）． 台形則が「どれだけ速く正確になるか」を深掘りする．読み飛ばして，次の 「落とし穴：端点の係数 1/2 を忘れると」 へ進んでよい．

台形則の誤差は 刻み幅 \(h\) の2乗に比例する（誤差 \(\propto h^2\)）ことが知られている． \(n\) を2倍にすると \(h\) は半分になるので，誤差はおよそ \(1/4\) になるはずである． 分割数 n を変えて，厳密解 1/3 との差を並べてみよう．

重要予測しよう（L1→L3）

n を 10, 20, 40, … と 2倍ずつにすると，誤差はどう減るか？ （半分？　\(1/4\)？　\(1/8\)？）

exact = 1/3
for n in [10, 20, 40, 80, 160]
    err = abs(trapezoid(0, 1, n) - exact)
    println("n = $n  ->  error = $err")
end
n = 10  ->  error = 0.0016666666666667607
n = 20  ->  error = 0.0004166666666667318
n = 40  ->  error = 0.00010416666666673846
n = 80  ->  error = 2.6041666666754004e-5
n = 160  ->  error = 6.510416666771768e-6

n を2倍にするたびに誤差がおよそ \(1/4\) ずつ小さくなっていれば， \(\,\)誤差 \(\propto h^2\,\) という理屈が確かめられたことになる（L3検証）．

誤差 vs n を両対数グラフで

誤差と n の関係は，両対数グラフにすると 直線になり，その 傾きが 収束の次数（ここでは \(-2\)）を表す．第4回の「対数で線形化」が，ここで効いてくる． 内包表記で誤差の列を一気に作り，xscale=:log10, yscale=:log10 で描く．

using Plots
ns   = [10, 20, 40, 80, 160, 320]
errs = [abs(trapezoid(0, 1, n) - 1/3) for n in ns]   # error sequence via comprehension
plot(ns, errs,
     xscale = :log10, yscale = :log10,
     marker = :circle,
     xlabel = "n (divisions)", ylabel = "error",
     title  = "trapezoid error (log-log)")

両対数で きれいな直線になり，n が10倍で誤差が100倍小さくなる （縦に2目盛り下がる）なら，傾きは \(-2\)，すなわち 誤差 \(\propto n^{-2} \propto h^2\) である．

落とし穴：端点の係数 1/2 を忘れると

台形則でいちばん多い失敗が，両端 \(f(a),\,f(b)\) の係数 \(1/2\) を忘れることである． 端点も内側と同じ係数 \(1\) で足してしまうと，台形則ではなく別の和になる． 次の trapezoid_bad は s = f(a) + f(b)（\(1/2\) 抜き）にした 誤った関数である．

警告落とし穴：端点係数 1/2 の欠落

下の関数は計算自体は止まる（エラーは出ない）が， 端点を余分に足しているぶん 厳密解 1/3 から系統的にずれる． 「エラーが出ない＝正しい」ではないことに注意．厳密解との照合で初めて気づける．

function trapezoid_bad(a, b, n)
    h = (b - a) / n
    s = f(a) + f(b)                # forgot to multiply by 1/2 (pitfall)
    for k in 1:n-1
        s += f(a + k*h)
    end
    return s * h
end
trapezoid_bad(0, 1, 100)           # an off value, not 1/3
0.33835000000000004
trapezoid_bad(0, 1, 1000)          # approaches 1/3 only like h (order 1), far slower
0.33383349999999995

正しい trapezoid は n=100 で誤差 \(\sim 10^{-5}\) だったのに対し， trapezoid_bad は端点を余分に足したぶん \(\,\frac{f(a)+f(b)}{2}h\,\) だけ上にずれる （この例では \(f(0)+f(1)=1\) なので \(h/2\)）．n を増やせば 1/3 に近づくが， ずれは \(h\) に比例して減るだけで，正しい台形則（\(h^2\)）より 桁違いに遅い． 厳密解 1/3 との照合（L2）だけでなく，誤差が \(h\) でしか減らない という減り方の違い（L3）が，この種の係数ミスをあぶり出す．

ノートAI が書いたコードの検証に

台形則は AI にもよく書かせるが，端点係数 \(1/2\) の欠落や， 左リーマン和（誤差 \(\propto h\)）を台形則（誤差 \(\propto h^2\)）と取り違える誤りが起きやすい． 「厳密解 1/3 への収束」と「誤差の減り方（\(h\) か \(h^2\) か）」の2点で照合すれば， コードが本当に台形則になっているかを見抜ける．

アルゴリズムを図に描く（収束ループの PAD）

収束ループは，「初期化 → 同じ処理を繰り返す → 打ち切り条件で抜ける」という骨組みである． 第3回の反復の箱にならって，次の形を手元で描いてみよう．

  • ループの外：s = 0.0，k = 1（初期化）
  • 反復の箱：term を計算 → s に足す → term < tol なら抜ける → k を1増やす

「初期化はループの外，打ち切りはループの中」という設計が，目で見て分かる．

今回のまとめ

  • 内包表記 [f(k) for k in …] は値の列を一気に作る（ブロードキャストの仲間）．sum(… for …) で級数和にも使える．
  • 収束ループ は while true … の中で if が条件を見て break で抜ける形．項が単調に小さくなるなら 有限回で必ず止まる．許容誤差を厳しくすると項数は増える．
  • 打ち切りを 等号（!=）で書くと止まらないことがある（小数はぴったりの値にならない）．不等号で打ち切り，反復上限も設ける．
  • 台形則は端点 \(f(a),f(b)\) を 係数 \(1/2\)，内側を係数 \(1\) で足す．function … end で関数にまとめる（f は外で定義）．
  • 検証は 厳密解 1/3 との照合（端点係数 \(1/2\) の欠落も，厳密解との差で気づく）．
  • （発展）誤差 \(\propto h^2\)：n を2倍にすると誤差は \(1/4\)，両対数グラフで傾き \(-2\)．
