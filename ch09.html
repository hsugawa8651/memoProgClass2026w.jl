第9回：整数・剰余と互除法

今回の背骨は 「整数は有限のビット世界，すなわち2の補数．だから溢れて一周する」 である． コンピュータの整数は，数学の整数（いくらでも大きくできる）とは違い， 決まったビット数の中に収められている．Int8（8ビット）で 溢れ（オーバーフロー） を 目で見て，bitstring で 2の補数 のしくみをのぞく． あわせて，整数の 除算・剰余（div・rem・mod）と， それらを使う ユークリッド互除法 を関数として書く．

ノート

整数（第9回）＝有限で溢れる，浮動小数点（第10回）＝丸めでズレる． この2回は対になっていて，あわせて 「計算機の数 ≠ 数学の数」 を学ぶ． 今回は前半（整数）を扱う．

整数は有限のビット世界（2の補数）

ふだん使う整数の型 Int64 は64ビットだが，溢れを 見える化 するために， ここではわざと小さな Int8（8ビット）を使う． 8ビットで表せる整数は −128 から 127 まで の256個だけである．

その範囲の両端は typemax（最大値）・typemin（最小値）で確かめられる．

typemax(Int8), typemin(Int8)    # the two ends of the range
(127, -128)

bitstring を使うと，その整数が どんなビットの並び（0と1） で表されているかが見える．

bitstring(Int8(127))            # how is 127 stored?
"01111111"

先頭が 0 で，残りの7ビットが 1111111 になっている． この 先頭のビット（最上位ビット，MSB）が符号を表す：0 なら正である．

重要予測しよう（L1）

bitstring(Int8(-1)) はどんな並びになるか？ 「-1 だから先頭が 1 で残りが…」と素直に考えると外れる．実行前に予想しよう．

bitstring(Int8(-1))             # compare with your prediction
"11111111"
ヒント2の補数（負の数の表し方）

全部1のビット並びが -1 になるのが 2の補数 という方式である． 直感に反するが，これには大きな利点がある： x のビット並びに 1 を足していくと，127 の次が -128 へ自然につながり， 1本の輪（リング）になる．だから「足し算回路」だけで負の数も正しく扱える． 深入りはしないが，「整数は有限の輪っかになっている」 とだけ覚えておこう．

オーバーフロー：有限だから一周する

整数が有限の輪なら，最大値の次に1を足すとどうなるか．

重要予測しよう（L1）

Int8(127) + Int8(1) はいくつか？ 数学なら 128 だが，Int8 の最大は 127 である．実行前に予想しよう．

Int8(127) + Int8(1)             # what does the sum become?
-128
警告落とし穴：整数オーバーフロー

Int8 の最大値 127 に 1 を足すと，128 ではなく -128（最小値） になる． エラーも警告も出ず，静かに間違った値を返すのがこわいところである． これが オーバーフロー（溢れて一周） ＝2の補数の輪が一周した瞬間である．

Int8(100) + Int8(100)           # 200 is out of range; what comes out?
-56

同じことは，ふだんの Int64（64ビット，範囲は約 ±9.2×10¹⁸）でも起こる． 重要なのは，整数どうしの加減乗算（+・-・*）は，溢れても警告もエラーも出さず， 静かに一周するということである．だから気づきにくい．

警告落とし穴：Int64 の加算も静かに溢れる

Int64 の最大値 typemax(Int64) に 1 を足すと，Int8 と同じく 最小値（負） にぐるっと一周する．エラーは出ない．

typemax(Int64) + 1              # what happens at the top end?
-9223372036854775808

発展：自作の階乗関数で型のしくみを見る

ノート

ここから先は 発展（必修ではない）．「同じコードが型によって結果を変える」しくみに 興味がある人向けである．読み飛ばして，次の 「整数の除算・剰余」 へ進んでよい．

階乗 n! = 1·2·⋯·n は急速に大きくなる．自分で myfactorial を定義してみよう （for と総和＝第3回，関数定義＝第7回）．

function myfactorial(n)
    p = one(n)                  # "1" of the same type as n (the key trick)
    for k in 1:n
        p = p * k
    end
    return p
end
myfactorial (generic function with 1 method)

同じ関数を，引数の型を変えて呼ぶ．

myfactorial(5)                  # check against 5! by hand
120
myfactorial(21)                 # does 21! fit in Int64?
-4249290049419214848
myfactorial(21.0)               # Float -> no overflow but approximate
5.109094217170944e19
myfactorial(big(21))            # BigInt -> grows in digits and stays exact
51090942171709440000
ノート同じコードが型ごとに違う ＝ 多重ディスパッチ
  • Int は静かに溢れ，Float は溢れず近似，BigInt は正確．myfactorial は1つしか書いていないのに， 型に応じて * の中身が自動で選ばれる（多重ディスパッチ）からである．
  • 初期値を 1 でなく one(n) にするのが技巧．型に合った「1」になり，myfactorial(0.0) も整数 1 でなく 1.0 と正しく返る（1:0 も 1:0.0 も空なので，ループは回らず one(n) がそのまま答え）．

落とし穴：myfactorial(3.2) は何を計算しているか

myfactorial に 小数 を渡しても，エラーは出ず それらしい数 が返る．だが正しいだろうか．

myfactorial(3.2)                # what does the loop actually multiply?
6.0

for k in 1:3.2 は 1.0, 2.0, 3.0 までしか回らず，小数部 .2 を黙って捨てている． 本当の 3.2! は ガンマ関数 \(\Gamma\) で \(n! = \Gamma(n+1)\) と定義される（SpecialFunctions.jl）．照合しよう．

using SpecialFunctions
gamma(3.2 + 1)                  # the gamma function at 4.2
7.756689535793179
警告「実行できた」≠「求めたものが得られた」

myfactorial は，書いたとおりに 1 × 2 × 3 を計算して 6.0 を返している． コードが壊れているのではない．3.2! を求めたつもりなら，得られたのは別の値である． 真の 3.2! は約 7.76 で，得られた 6.0 とは 1.7 以上も違う．

エラーは出ないので，既知の真値（ここではガンマ関数）と照合して初めて気づく． これが検証の核心である（第10回からは，これを L3 として扱う）． myfactorial は 整数向け，非整数の階乗は ガンマ関数，と心得る （整数では一致：gamma(6) == myfactorial(5) == 120）．

整数の除算・剰余

第1回で 7 / 2 が 3.5（小数）になることを見た． 整数の世界の 割り算は，商と余りに分けて考える．

  • div(a, b)：整商（小数を切り捨てた商）．第3回で使った a ÷ b と同じもの
  • rem(a, b)：剰余（割り算の余り）
  • mod(a, b)：剰余（こちらも余り．負の数で rem と違う）
div(17, 5)                      # 3 (integer quotient: the 3 in 17 = 5*3 + 2)
3

正の数どうしなら，rem と mod は同じ結果になる．

rem(17, 5), mod(17, 5)          # same or different?
(2, 2)
重要予測しよう（L1）

rem(-7, 3) と mod(-7, 3) はそれぞれいくつか？ 負の数を割ると，2つは違う値になる．実行前に予想しよう．

rem(-7, 3), mod(-7, 3)          # now compare the signs
(-1, 2)
警告落とし穴：rem と mod の符号が違う

負の数では rem と mod で 符号の基準が違う．

  • rem(-7, 3) は 割られる数 -7 の符号に合わせて -1．
  • mod(-7, 3) は 割る数 3 の符号に合わせて 2（つねに 0 以上）．

「余りはひとつ」と思い込むと間違える．どちらの符号がほしいかで使い分ける．

整数どうしでも / を使うと，商と余りではなく 実数の割り算になり， 結果は 小数（浮動小数点数） になる．型が変わることに注意する．

17 / 5                          # 3.4 (real division; a float, not an integer)
3.4
ヒント

div(17, 5) は 3（Int）で，17 / 5 は 3.4（Float64）． 整数の割り算がほしいなら div，小数がほしいなら /．用途で使い分ける．

ユークリッド互除法（最大公約数）

剰余 rem を使う代表的なアルゴリズムが ユークリッド互除法 である． 2つの整数の 最大公約数（gcd） を，次の事実だけで求める：

a と b の最大公約数は，b と rem(a, b) の最大公約数に等しい．

この置き換えを繰り返すと余りは小さくなっていき，やがて 0 になる． 余りが 0 になったときの割る数が最大公約数である． なぜ必ず 0 に届くのかは，次の節で考える．

これを 関数 にまとめる（第7回の関数化のモチーフの続き）．

回数が決まらない繰り返し：while

第3回の for は，走査する値を 先に 用意しておく形だった． 互除法は 何回で終わるかが，やってみるまで分からない． こういう繰り返しには while 条件 … end を使う．条件が成り立つ 間，中身を繰り返す．

重要予測しよう（L1）

下の mygcd の while b != 0 は，必ず止まるだろうか． 止まると言えるなら，その理由は何か．

止まる理由は，余りの性質にある． rem(a, b) は b より小さい 0 以上の整数 である． だから b は繰り返すたびに小さくなり，0 以上なので，有限回で必ず 0 に届く． 「止まる理由を言えること」が，while を書くときの作法である （止まらない例は第12回で扱う）．

ノート同時に置き換える

a を b に，b を余りに 同時に 置き換えたい． 第5回の 同時代入 を使えば1行で書ける． 右辺が先に計算されるので，rem(a, b) には 置き換える前の a と b が使われる．

function mygcd(a, b)
    while b != 0              # repeat until the remainder becomes 0
        a, b = b, rem(a, b)   # update both at once (right-hand side is read first)
    end
    return a              # when b is 0, a is the greatest common divisor
end
mygcd (generic function with 1 method)
ヒント予測しよう（L1）

mygcd(48, 36) の各反復で a と b がどう変わるか，実行前に表を埋めてみよう． rem(a, b) の欄には，置き換える前の a と b から計算した余りを書く．

反復 a b rem(a, b)
開始 48 36
1回目後
2回目後
…

「頭の中でループを回す（トレース）」と，アルゴリズムの動きが腑に落ちる．

重要予測しよう（L1）／既知の答えと照合（L2）

mygcd(48, 36) はいくつか？ 48 = 2^4 × 3，36 = 2^2 × 3^2 なので，最大公約数は 手計算で 12 とわかる． 実行前に予想してから，計算結果が 既知の 12 と一致するか確かめよう（L2検証）．

mygcd(48, 36)                   # compare with the 12 computed by hand
12

Julia には標準の gcd 関数もある．自作の mygcd と 同じ結果になることを確かめれば， 実装が正しいことの 裏付け がもうひとつ増える（L2）． ただし一致は 証拠 であって証明ではない．いくつかの入力で合っても，全部の入力で合う保証はない．

gcd(48, 36)                     # does the library agree with mygcd?
12

今回のまとめ

  • 整数は 有限のビット世界＝2の補数．Int8 は −128〜127（typemax・typemin）．
  • bitstring で並びが見える．全部1が -1（2の補数）．整数は 1本の輪になっている．
  • オーバーフロー：Int8(127)+Int8(1) は -128，自作の myfactorial(21) は負． エラーが出ずに静かに間違う（有限だから一周する）．
  • 整数の割り算は div（整商）・rem・mod．負の数で rem と mod は符号が違う． 17 / 5 は小数（型が変わる）．
  • ユークリッド互除法 mygcd は，余りが 0 になるまで rem を繰り返す． 既知の gcd と 照合して正しさを確かめる（L2）．
  • 次回（第10回）は 浮動小数点＝丸めでズレる．整数（有限で溢れる）と対で， 「計算機の数 ≠ 数学の数」 を完成させる．
